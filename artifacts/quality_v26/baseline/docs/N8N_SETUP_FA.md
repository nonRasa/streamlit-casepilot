# راه‌اندازی گردش‌کار روی سایت

وضعیت معماری دوم: فایل جاری ۱۳ گره دارد. هستهٔ پایتون تمام مراحل امبدینگ، بازیابی، بازرتبه‌بندی، تولید، داوری و اصلاح محدود را اجرا می‌کند؛ گره کنترل قرارداد مسیر نوبت، پاسخ داوری‌نشده یا خروجی خارج از سقف را رد می‌کند. سه مسیر نوبت، بازبینی انسانی و اجرا مستقل‌اند. مهلت درخواست نوبت ۲۱۰ ثانیه و سقف اجرای گردش‌کار ۲۴۰ ثانیه است. داور مدل مجوز ثبت صادر نمی‌کند.

فایل آماده:

```text
workflows/casepilot_main.json
```

طراحی: گردش‌کار سه ورودی مستقل دارد: دریافت گزارش، بازبینی نگه‌دارنده، و اجرای پیشنهاد تأییدشده. مسیر تولید پاسخ به تأیید وصل نشده است. نگه‌دارنده باید پیشنهاد را ببیند و تصمیم واقعی بگیرد. انتظار، وضعیت و مجوز در پایگاه پایتون می‌مانند؛ قطع اجرای گردش‌کار آن‌ها را پاک نمی‌کند.

## مرحلهٔ سرور پایتون

پیش‌نیاز: سرور باید روشن و برای سایت شما قابل دسترسی باشد. اگر سایت ابری است، نشانی محلی لپ‌تاپ مناسب نیست. سرور را روی میزبان در دسترس با اتصال امن و فضای پایدار اجرا کنید. نصب برنامهٔ پایتون در سایت گردش‌کار به‌صورت خودکار انجام نمی‌شود.

```powershell
python run.py serve --host 0.0.0.0 --port 8765
```

راهنما: برای نمایش محلی می‌توان از نشانی محلی استفاده کرد. برای میزبانی عمومی، نشانی امن واقعی سرور را در سه گره درخواست جایگزین کنید. ابزار تولید گردش‌کار همین کار را انجام می‌دهد؛ فقط نشانی سرور خودتان را وارد کنید. این ابزار کلید یا توکن دریافت نمی‌کند.

```powershell
python scripts/generate_artifacts.py --workflow-only --backend-url "https://YOUR-ACTUAL-BACKEND"
```

نکته: گزینهٔ تولید فقط گردش‌کار، نوت‌بوک و قراردادها را حفظ می‌کند. اجرای ابزار بدون این گزینه، آن‌ها را نیز بازسازی می‌کند؛ پیش از آن تغییرهای شخصی نوت‌بوک را نگه دارید. گزارش وضعیت اتصال واقعی از اجرای واقعی تأیید می‌شود.

## مرحلهٔ واردکردن و اعتبارنامه

مرحلهٔ نخست: فایل گردش‌کار را از گزینهٔ واردکردن فایل انتخاب کنید. نسخهٔ ساخته‌شده غیرفعال است و دادهٔ نمونه یا کلید در آن ذخیره نشده است.

مرحلهٔ دوم: چهار اعتبارنامهٔ سربرگ بسازید؛ نام آن‌ها در گره‌ها آمده است. برای ورودی‌های سایت، دو مقدار دلخواه جدا بسازید. برای درخواست‌های سرور، مقادیر باید با توکن اپراتور و بازبین محیط سرور یکسان باشند. نام سربرگ هر چهار مورد، مجوز استاندارد و مقدار آن پیشوند حامل به‌همراه توکن است.

نام اعتبارنامه‌ها و شکل سربرگ:

```text
CasePilot Operator Webhook
CasePilot Reviewer Webhook
CasePilot Operator API
CasePilot Reviewer API

Header name: Authorization
Header value: Bearer YOUR_TOKEN
```

مرحلهٔ سوم: اعتبارنامهٔ اپراتور سرور را فقط به درخواست نوبت کاربر وصل کنید. اعتبارنامهٔ بازبین سرور فقط به درخواست بازبینی و اجرا وصل می‌شود. اعتبارنامه‌های ورودی سایت نیز مطابق همین دو نقش جدا انتخاب شوند. شناسه‌های اعتبارنامهٔ شخصی در فایل تحویل نیستند؛ پس انتخاب آن‌ها پس از واردکردن ضروری است.

## مرحلهٔ آزمایش انسانی

مرحلهٔ نخست: ورودی نوبت را در حالت آزمایشی گوش بدهید و بدنهٔ فایل `examples/turn.json` را بفرستید. نتیجه باید شامل پاسخ، خلاصه و پیشنهاد دارای شناسه و هش باشد. شمار نظرهای واقعی رهگیر هنوز صفر است.

مرحلهٔ دوم: متن و شاهدها را بخوانید. شناسه و هش همان پیشنهاد را به ورودی بازبینی بفرستید و تصمیم رد، ویرایش یا تأیید را خودتان انتخاب کنید. فایل `examples/review.json` پیش‌فرض رد است. متن داده یا مدل نمی‌تواند تصمیم تأیید را صادر کند.

مرحلهٔ سوم: فقط پس از تأیید، شناسهٔ مجوز برگشتی را همراه پرونده و پیشنهاد به ورودی اجرا بفرستید. فایل `examples/execute.json` شکل ورودی را نشان می‌دهد. تکرار همین درخواست باید همان نتیجهٔ ثبت‌شده را برگرداند؛ شمار نظرها یکی بماند.

مرحلهٔ چهارم: رد، ویرایش، رسیدن اطلاعات تازه، خاموش و روشن‌شدن سرور و تلاش دوباره را امتحان کنید. پس از ویرایش، شناسهٔ پیشنهاد عوض می‌شود و تأیید تازه لازم است. خطای شبکه را با نتیجهٔ واقعی رهگیر بررسی کنید؛ تکرار کور مجوز تازه نسازد.

مسیرهای تولیدی سایت:

```text
POST /webhook/casepilot-turn
POST /webhook/casepilot-review
POST /webhook/casepilot-execute
```

محدودیت: آزمون محلی سرور و کنترل ساختار فایل انجام شده است؛ واردکردن، انتخاب اعتبارنامه و اجرای واقعی روی نسخهٔ سایت شما هنوز انجام نشده‌اند. برنامه برای اجرای اصلی به سایت وابسته نیست و خط فرمان و رابط محلی کامل دارند. واردکردن فایل، مدرک موفقیت اجرای سایت محسوب نمی‌شود.

قرارداد جاری: گره کنترل، نسخهٔ `v2.2-quality`، تطابق نسخهٔ پیش‌نویس و داوری در حالت واقعی، ردپای خرابی قرارداد و خلاصهٔ قابل‌اقدام ارجاع را هم بررسی می‌کند. چهارده کنترل محلی قرارداد و گراف عبور کرده‌اند؛ این نتیجه اجرای واقعی روی سایت نیست. تأیید و اجرا همچنان دو ورودی مستقل انسانی هستند.

مرجع: قالب گردش‌کار و رفتار ورودی‌ها بر اساس [راهنمای رسمی واردکردن](https://docs.n8n.io/workflows/export-import/)، [راهنمای رسمی وب‌هوک](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/) و [راهنمای رسمی درخواست](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.httprequest/) تنظیم شده‌اند.
