# پروژهٔ دستیار بررسی و پیگیری پرونده

معرفی: پروژهٔ `CasePilot` دو بخش صورت پروژه را پیاده می‌کند: بررسی مستند گزارش خطای `Streamlit`، و پیگیری چندنوبتی همان پرونده با حافظهٔ پایدار، بازبینی انسانی و اجرای قابل بازگشت روی رهگیر محلی.

وضعیت: نسخهٔ بدون کلید قابل اجراست. مدل آزمایشی یک سیاست قطعی است؛ خروجی آن نتیجهٔ مدل زبانی واقعی نیست. اتصال متیس، دفتر هزینه و مسیر ارزیابی واقعی آماده‌اند، اما تا دریافت کلید و تنظیم تعرفه هیچ درخواست مدل ارسال نمی‌شود. فایل گردش‌کار برای واردکردن توسط شما آماده شده است؛ اجرای آن روی سایت شما هنوز تأیید نشده است.

## شروع سریع

راهنمای ویندوز: فایل `START.ps1` رابط محلی را اجرا و دو توکن محلی لازم را در همان ترمینال نشان می‌دهد. فایل `run.ps1` ابتدا محیط مجازی پروژه، سپس پایتون همراه برنامهٔ کدکس و سپس نصب معمول پایتون را پیدا می‌کند؛ بنابراین روی این دستگاه به فرمان عمومی پایتون وابسته نیست.

```powershell
.\run.ps1 run.py doctor
.\START.ps1
```

توضیح: فرمان‌های عمومی پایتون در ادامه را می‌توانید با پیشوند زیر نیز اجرا کنید. اگر سیاست ترمینال اجرای اسکریپت محلی را مسدود کرد، دستور دوم فقط برای همان فرایند قابل استفاده است.

```powershell
.\run.ps1 scripts/run_tests.py
powershell -NoProfile -ExecutionPolicy Bypass -File .\START.ps1
```

پیش‌نیاز: نسخهٔ `Python` باید حداقل ۳٫۱۱ باشد. هسته فقط از کتابخانهٔ استاندارد استفاده می‌کند؛ اجرای برنامه، آزمون‌ها و ارزیابی بدون نصب بسته و بدون اینترنت ممکن است. دستورات را از ریشهٔ همین پروژه اجرا کنید.

```powershell
python run.py doctor
python scripts/run_tests.py
python run.py demo
python scripts/evaluate.py --split dev
```

توضیح: دستور دمو دو نوبت گفت‌وگو، تأیید توسط بازیگر آزمایشی، یک ثبت و تلاش مجدد بدون تکرار را روی پایگاه موقت اجرا می‌کند. این تأیید، بازبینی انسانی واقعی محسوب نمی‌شود. فایل‌های نتیجه و ردپا در پوشهٔ زیر ذخیره می‌شوند.

```text
artifacts/demo.json
artifacts/demo_trace.json
artifacts/test_results.json
artifacts/offline/dev/
```

## نوت‌بوک مانند تمرین‌ها

راهنما: فایل `CasePilot_project.ipynb` مسیر داده، بازیابی، پاسخ، تأیید، اجرا، آزمون و ارزیابی را مرحله‌به‌مرحله دارد. برای اجرای نوت‌بوک، نصب ابزارهای اختیاری کافی است. بخش واقعی پیش‌فرض خاموش و تصمیم بازبین پیش‌فرض رد است.

```powershell
python -m pip install -e ".[notebook]"
python -m jupyter lab CasePilot_project.ipynb
```

توضیح: نسخه‌های دقیق ابزارهایی که برای اجرای همین نوت‌بوک آزموده شده‌اند در `requirements-notebook.lock.txt` آمده‌اند؛ این فایل برای اجرای خودکار نوت‌بوک است و رابط کامل آزمایشگاه را نصب نمی‌کند. نوت‌بوک همراه بسته با هشت سلول اجرایی، بدون کلید و بدون خطا اجرا شده است.

```powershell
.\run.ps1 -m pip install -r requirements-notebook.lock.txt
.\run.ps1 scripts/execute_notebook.py
```

## رابط فارسی محلی

راهنما: دو توکن جدا برای اپراتور و نگه‌دارنده بسازید و آن‌ها را در کادر مناسب رابط وارد کنید. توکن اپراتور نمی‌تواند تأیید یا اجرا کند. کلید متیس در مرورگر وارد نمی‌شود. این نمونه توکن‌ها را فقط در محیط همان ترمینال نگه می‌دارد؛ آن‌ها را در گزارش یا مخزن ذخیره نکنید.

```powershell
$env:CASEPILOT_MODE = "replay"
$env:CASEPILOT_API_TOKEN = [guid]::NewGuid().ToString("N")
$env:CASEPILOT_REVIEW_TOKEN = [guid]::NewGuid().ToString("N")
python run.py serve
```

نشانی رابط:

```text
http://127.0.0.1:8765
```

توضیح: مقدار توکن‌های ساخته‌شده را از متغیرهای همان ترمینال به کادرهای رابط منتقل کنید. واقعیت‌های اصلاح‌شده در کادر ساخت‌یافته وارد می‌شوند؛ کلیدهای مجاز شامل نسخهٔ محصول، نسخهٔ پایتون، سیستم‌عامل، مرورگر، محیط استقرار، بازتولید و تأیید رفع‌اند. مشخصات ناقص حدس زده نمی‌شوند.

```json
{
  "streamlit_version": "1.49.0",
  "python_version": "3.11",
  "deployment": "docker",
  "reproducible": true,
  "resolved": false
}
```

فرایند: گزارش را ارسال کنید؛ شاهدها و خلاصه را بخوانید؛ پیشنهاد را رد، اصلاح یا تأیید کنید؛ سپس اجرای صریح را بزنید. اصلاح پیشنهاد، تأیید تازه می‌خواهد. تغییر پرونده یا رسیدن اطلاعات جدید، مجوز قبلی را نامعتبر می‌کند. صفحهٔ مرورگر توکن و مجوز را در حافظه نگه می‌دارد؛ پایگاه داده وضعیت پرونده و انتظار برای بازبینی را پایدار نگه می‌دارد.

## گردش‌کار قابل واردکردن

فایل `casepilot_main.json` سه ورودی مستقل برای نوبت کاربر، بازبینی انسانی و اجرای تأییدشده دارد. هیچ اتصال خودکار از تولید پاسخ به تأیید وجود ندارد. منطق اصلی در برنامهٔ پایتون باقی می‌ماند.

```text
workflows/casepilot_main.json
```

راهنما: مراحل واردکردن، تنظیم اعتبارنامه‌ها و نشانی سرور در فایل زیر آمده است. سایت `n8n` باید به سرور پایتون دسترسی شبکه داشته باشد؛ نشانی محلی لپ‌تاپ از یک سایت ابری قابل دسترسی نیست. واردکردن تنها فایل گردش‌کار، سرور پایتون را اجرا نمی‌کند.

```text
docs/N8N_SETUP_FA.md
```

## داده و ارزیابی

داده: نسخهٔ ثابت شامل ۲۴۵ گزارش واقعی و ۳۹ منبع رسمی است. تنها بخشی از گفت‌وگوها دریافت شده‌اند؛ شمار دقیق و وضعیت کامل‌بودن هر گفت‌وگو در فراداده ثبت است. بدنهٔ گزارش‌ها، کد و خطا حفظ می‌شوند؛ تصاویر خوانده‌نشده شاهد محسوب نمی‌شوند. اطلاعات شخصی غیرضروری و مقادیر شبیه کلید پاک می‌شوند.

ارزیابی: مجموعهٔ نهایی ۱۵ پروندهٔ توسعه و ۱۵ پروندهٔ آزمون تازه دارد. نمونه‌های آزمون اولیه پس از استفاده برای بررسی مقدماتی بازنشسته شدند و همچنان از بازیابی کنار گذاشته‌اند. کد پیش از انتخاب آزمون تازه قفل و هش آن ثبت شد. ده سناریوی چندنوبتی، شامل پنج سناریوی آزمون، در فایل جدا قرار دارند. پاسخ‌های تکمیلی آن‌ها طراحی‌شده‌اند و گفت‌وگوی واقعی معرفی نمی‌شوند.

راهنما: ارزیابی نهایی را پس از تصمیم‌های توسعه اجرا کنید. اجرای بدون کلید صرفاً زیرساخت و مسیرها را می‌سنجد. گزارش عدد پوشش منبع را از شاخص سادهٔ مسیر تصمیم و از داوری انسانی پاسخ جدا می‌کند.

```powershell
python scripts/evaluate.py --split test
python scripts/adversarial.py
python scripts/verify_package.py
```

## ساختار تحویل

- پوشهٔ `src/casepilot` شامل عامل، بازیابی، کنترل استناد، رهگیر، اتصال مدل، حسابداری، خط فرمان و رابط است.
- پوشهٔ `data` شامل نسخهٔ داده، قطعه‌های مجاز و فهرست هش‌هاست؛ پاسخ خام شبکه وارد بستهٔ تحویل نمی‌شود.
- پوشهٔ `eval` شامل پرونده‌ها، سناریوها، معیارها و سابقهٔ قفل آزمون است؛ این پوشه به مدل داده نمی‌شود.
- پوشهٔ `policies` و پوشهٔ `schemas` شامل حدود اجرا و قراردادهای ابزار و پاسخ‌اند.
- پوشهٔ `tests` و پوشهٔ `scripts` شامل آزمون، دریافت داده، آماده‌سازی، ارزیابی و کنترل بسته‌اند.
- پوشهٔ `artifacts` شامل نتایج واقعی اجرای محلی، ردپا، گزارش هزینهٔ صفر و وضعیت اجرای واقعی است.
- پوشهٔ `docs` شامل معماری، راهنمای داده و ارزیابی، اجرای واقعی، گردش‌کار و دفاع است.
- فایل `report.md` گزارش نتایج و محدودیت‌های همین نسخه است.

## حدود قابل دفاع

محدودیت: کنترل خودکار استناد، وجود نقل‌قول و معتبر بودن شناسهٔ منبع را می‌سنجد؛ صحت معنایی کامل و مناسب‌بودن راهکار برای نسخهٔ کاربر را تضمین نمی‌کند. گزارش مشابه اثبات علت نیست. همهٔ تغییرات نیازمند بازبینی‌اند. اجرای کد گزارش، تولید وصله و نوشتن در مخزن واقعی در برنامه وجود ندارد.

محدودیت: این نسخه جایگزین نتیجهٔ واقعی مدل و دفاع اعضای تیم نیست. سهم اعضا باید بر اساس کار واقعی گروه در گزارش تکمیل شود. دادهٔ آزمون توسط نویسندهٔ مجموعه بررسی شده است؛ آزمون تازه برای تنظیم بازیابی استفاده نشده، اما معیار کاملاً کور بیرونی نیست.

مرجع: الزامات از [سند پروژهٔ پایان دوره](https://docs.google.com/document/d/1N13vE1IoqTDlEFndNOULGgXYIU2SER6pVkwEG8iPLYM/edit?tab=t.0) استخراج شده‌اند. قواعد خاص و بودجهٔ تمرین‌های قبلی به این پروژه منتقل نشده‌اند.
