# نتیجهٔ v2.14: منع درخواست تکراری و بازیابی شاهد

تاریخ: ۲۰۲۶-۱۰-۰۹. پروتکل: `docs/QUALITY_V214_PROTOCOL_FA.md`.
این مرحله تنها از دادهٔ توسعه و corpus منجمد استفاده کرد؛ دادهٔ نهایی
و برچسب آن برای تنظیم تغییر به کار نرفت. اجرای زندهٔ تازه انجام نشد.

## تغییرات

- موجودی گزارش اکنون خطای نام‌دارِ ارائه‌شده را عیناً ثبت می‌کند.
- داوری قطعی، درخواست دوبارهٔ متن «خطای کامل» و تعریف کامل کلاسِ موجود
  را برای تصمیم‌های `ask` و `escalate` رد می‌کند. درخواست جزئیات واقعاً
  غایب یا آزمایش با شرط تازه همچنان مجاز است.
- پرس‌وجوی بازیابی، Checklist را حذف می‌کند و Summary فنیِ پس از آن
  را نگه می‌دارد. در حالت بدون بردار، حداکثر دو مرجع API که نامشان
  صریحاً در گزارش است اولویت می‌گیرند و هر منبع حداکثر دو قطعه دارد.
  نسخهٔ مرجع همچنان با نسخهٔ پرونده تطبیق داده و هشدار داده می‌شود؛
  حضور مرجع به‌تنهایی ادعای علت یا رفع مشکل را ثابت نمی‌کند.

جدید کد فعلی است. معیار، تعداد شناسهٔ منبع برچسب‌خورده در پنج نامزد

صورتحساب ارائه‌دهنده مستقل تأیید نشده است.

## محدودیت و گام بعد

این سنجش کیفیت نامزدهای بازیابی را نشان می‌دهد، نه کیفیت پاسخ نهایی،
پذیرش داور یا ترجیح انسانی. منابع API موجود برای نسخهٔ ۱٫۴۹٫۰ هستند

پاسخ زنده و داوری انسانیِ کور ارزیابی شود. مجموعهٔ نهایی باید تا
پایان تنظیمات دست‌نخورده بماند.
