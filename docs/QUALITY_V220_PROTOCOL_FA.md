# پروتکل پیش از اجرا: نگه‌داشتن شاهد رسمیِ مستقیم

تاریخ: ۲۰۲۶-۱۰-۱۰. فرضیه: در مسیر بازیابی واژگانی بدون embedding، گزارش‌های مشابه جای سند رسمیِ مرتبط با API/عنوان مسئله را در بستهٔ پنج‌قطعه‌ای می‌گیرند. تغییرِ واحد این آزمایش، انتخاب نامزدهای بازیابی است؛ مدل، داور، داده و اندازهٔ بسته تغییر نمی‌کنند.

برای ۱۵ پروندهٔ `dev` در `eval/cases.json`، با همان `data/corpus_v2.json` و همان پرس‌وجوی `retrieval_query`، ابتدا مسیر فعلی `no_dense` و سپس مسیر آزمایشی اجرا شود. مسیر آزمایشی از ۱۰۰ نتیجهٔ واژگانی، حداکثر دو سند رسمی با تطابق مستقیم نام API یا واژه‌های معنی‌دار عنوان گزارش را پیش از گزارش‌های مشابه در هشت نامزد قرار می‌دهد. سند با نسخهٔ صریحاً نامنطبق برای بستهٔ نهایی حذف می‌شود؛ سند با نسخهٔ نامعلوم همچنان «نامعلوم» است. انتخاب به شناسهٔ پرونده، برچسب‌های ارزیابی یا پاسخ مرجع دسترسی ندارد.

معیار اصلیِ آفلاین: تعداد پرونده‌های توسعه که حداقل یک `relevant_source_id` از برچسب‌های موجودشان به بستهٔ پنج‌قطعه‌ای می‌رسد. معیارهای جانبی: شمار اصابت‌ها، پوشش سند رسمی، نسخهٔ نامنطبق/نامعلوم، طول متن و پرونده‌های بدترشده. این برچسب‌ها فقط ارتباط موضوعی‌اند؛ صحت ادعا، سازگاری نسخه و کیفیت پاسخ را ثابت نمی‌کنند. اجرای آفلاین پیش از بازرتبه‌بند مدلی است و درخواست API ندارد.

در صورت بهتر شدن معیار اصلی بدون افزایش شاهدِ نسخه‌نامنطبق، کد انتخاب نامزد حفظ و آزمون‌های محلی اجرا شود. سپس تنها با دسترسی معتبر، دفتر هزینهٔ روشن و سقف کل پیشین ۰٫۳۰ دلار، یک زوج زندهٔ کوچک روی `GH9218` با مدل و ورودی یکسان اجرا شود؛ پاسخ خام، رد/قبول واقعی داور، نخستین اقدام، تعداد فراخوانی‌ها و هزینه جداگانه گزارش شوند. اگر شرط زنده فراهم نبود، نتیجه فقط «بهبود بازیابی آفلاین» نامیده شود. مجموعهٔ `final` برای تنظیم استفاده نشود.
